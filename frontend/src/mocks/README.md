# mocks/

A mock implementation of the TaskFlow REST API built with
[MSW](https://mswjs.io). It intercepts real HTTP requests, so application code
(services, hooks, components) runs exactly as it will against the real backend.
Nothing here is imported by application code.

- **Development:** enabled when `VITE_ENABLE_API_MOCKS=true` (the default in
  `.env.development`). Set it to `false` once the backend is running. Production
  builds never load the mocks.
- **Tests:** `src/test/setup.ts` runs the same handlers in Node, so tests exercise
  the API contract end to end. Override a handler per test with `server.use(...)`.

| File            | Purpose                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| `handlers.ts`   | Endpoint definitions — the API contract the backend must implement            |
| `db.ts`         | Seeded in-memory store (jobs, executions, schedules) + dashboard aggregations |
| `schedules.ts`  | Reference scheduler: firing, overlap policy, no-backfill, pause/resume rules  |
| `events.ts`     | Event bus behind the `GET /events` SSE stream                                 |
| `simulation.ts` | Browser-only clock: fires schedules, runs jobs, emits progress and events     |
| `taskTypes.ts`  | Registered task types, and which of them report progress                      |
| `browser.ts`    | Service-worker setup for development (starts the simulation)                  |

The SSE handler is created only in the browser (`createLiveEventsHandler`), since MSW
can't build one without `EventSource`. Tests drive live updates with a fake EventSource
instead (`src/test/fakeEventSource.ts`).

`public/mockServiceWorker.js` is generated by MSW (`npx msw init public`) — don't
edit it by hand.
